# n8n — workflows متجر العصار

n8n يعمل على جهاز المدير (عبر ngrok). لذلك التصميم **سحب (pull)** وليس دفعاً:
الأحداث تُحفظ في `notification_outbox`، وn8n يسحبها كل دقيقة. إن كان الجهاز مطفأً لا يضيع شيء؛ تُرسل عند عودته.
n8n لا يحسب شيئاً ولا يعدّل المخزون أو الطلبات: يقرأ نصاً جاهزاً ويرسله فقط.

## الاعتماديات (Credentials)
| الاسم في n8n | النوع | المحتوى |
|---|---|---|
| `Header Auth account 6` | Header Auth | Name: `x-alassar-key` — Value: المفتاح من `/admin/settings/integrations` (يُعرض مرة واحدة) |
| `Telegram account 12` | Telegram API | بوت المدير (موجود مسبقاً). المحادثة: `972546610` |

مفتاح التكامل لا يسمح إلا بـ: `notifications_claim`، `notifications_complete`، `notifications_daily_report`.
يُخزَّن في القاعدة مجزأً (sha256). إنشاء مفتاح جديد يبطل القديم فوراً.
ترويسة `apikey` في العقد هي المفتاح العام (publishable) المصمم ليكون علنياً.

## Workflow 1 — إشعارات Telegram (`iO8ts5Rrr4JRCr4C`)
- **Trigger:** كل دقيقة.
- **سحب الإشعارات:** `POST /rest/v1/rpc/notifications_claim {p_channel:"telegram", p_limit:10}` ← مصفوفة `{event_id, event_type, attempt, text}` (0 عنصر = لا شيء).
- **إرسال إلى Telegram:** HTML، `onError: continueRegularOutput` حتى لا يوقف فشل رسالة واحدة البقية.
- **تسجيل نتيجة الإرسال:** `notifications_complete {p_event_id, p_success, p_error}` (الرد نص عادي: `sent`/`failed`/`dead`/`ignored`، لذا Response Format = Text).
- **منع التكرار:** السحب يقفل الحدث (`processing`)، ولا يُعاد إلا إذا علق أكثر من 10 دقائق.
- **إعادة المحاولة:** عند الفشل بتأخير متصاعد (2، 4، 8… حتى 60 دقيقة)، وبعد 5 محاولات يصبح `dead` ويظهر في لوحة التكاملات.
- **الأحداث:** طلب جديد، اختيار تحويل بنكي، انتهاء حجز، دخول المدير للوحة.
- **الخصوصية:** لا اسم زبون ولا هاتف ولا عنوان؛ ملخص + رابط الطلب في اللوحة (محمي بالدخول).
- لا تُحفظ التشغيلات الناجحة (1440 تشغيلاً يومياً)؛ الفاشلة تُحفظ.

## Workflow 2 — التقرير اليومي (`y5zWy1vIrVrygBCc`)
- **Trigger:** `0 23 * * *` بتوقيت **Asia/Gaza** (مضبوط في إعدادات الـ workflow، ويتبع التوقيت الصيفي تلقائياً).
- إن فات الموعد (الجهاز مطفأ): `misfirePolicy: coalesce` يشغّله مرة واحدة عند العودة.
- **جلب التقرير:** `notifications_daily_report` ← نص جاهز: المبيعات المؤكدة، الإيراد، رسوم التوصيل، ربح المدير، مستحقات المحل،
  بنود بلا ربح مسجل، الطلبات الجديدة/الملغاة/المسلمة، بانتظار التأكيد، تحويلات بانتظار المراجعة، الأكثر مبيعاً، المخزون المنخفض.
- إعادة محاولة 3 مرات للجلب والإرسال.
